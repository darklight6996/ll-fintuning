This is done so that a freshly migrated dMSA can seamlessly take over wherever the old account was used. The flaw is that the KDC never verifies that the migration was actually authorized. It trusts the link attribute at face value. As a result, any principal with CreateChild rights for msDS-DelegatedManagedServiceAccount objects on any OU (a permission that is not normally considered privileged) can create a dMSA, set its msDS-ManagedAccountPrecededByLink to point at a high-value target like Administrator, and request a TGT. The resulting ticket’s PAC contains Domain Admin group membership.
