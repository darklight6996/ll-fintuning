SSH Background At this point, it’s worth a quick diversion into some background on how SSH authentication works. When I type ssh root@10.1.1.200 , the client will generate a list of private keys that it might try to use for auth. That could be keys in ~/.ssh , or any given with -i in the command line. From each private key, it will identify the associated public key (by looking for the matching .pub file, or if it can’t find the .pub file, and the private key is of a newer format, extracting the public key embedded in it), and send each of those public keys to the server. The server will look at each public key and make a decision as to if that user would be allowed to connect.
